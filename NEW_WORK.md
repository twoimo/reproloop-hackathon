## Precise description of the faulty/fixed control

Both APKs are built from the same Kotlin sources and resources by
`android/build.sh`. The only build input that differs is a generated constant,
`BuildConfig.FAULTY` (true for the faulty build, false for the fixed build).
In the domain code the single behavioural difference is the Cancel handler line
`if (faulty) put(id, draft)` in `android/src/com/tinyburn/reproloop/lab/Domain.kt`:
the faulty build persists the unsaved draft on Cancel, the fixed build does not.
That one-line guarded behaviour and its flag were written by the developer (with
AI-assisted implementation). ReproLoop did not find, write or apply this repair.
No automatic repair, patch generation or fix suggestion is claimed anywhere.
